# Bugfix guide

## 1. Triage: classify before touching code

| Class | Meaning | Regression test | Fix goes to |
|---|---|---|---|
| `vip` | the VIP code is wrong (false failure, missed violation, wrong coverage) | a qualification test: a positive trace that stays silent or a negative trace that must fire exactly once | the checker, monitor, driver, sequence, coverage |
| `trace` | an ID, a check expression, or an evidence entry is wrong | a lint expectation or the trace whose expression changed | the specification row (this is a spec change: feature run) or the evidence |
| `counterpart` | the independent qualification model is wrong | the trace that exposed it, plus a check of the counterpart against the standard | `qual/<tag>_counterpart.sv` |
| `environment` | tool, command, or filelist problem | the failing command | the run settings or filelist |
| `dut` | the design under test violates the protocol: not a VIP bug | none | close as `wontfix` with the reason |
| `spec` | the specification itself is wrong or incomplete | none in this run | stop; start a feature run (a specification change needs Gate 1) |

A reported "VIP failure" is a `dut` defect when the check's expression matches the standard and the DUT violates it. Prove it with the standard clause and the waveform or log line before classifying.

## 2. Reproduce small, read little

1. Find the check: `vip query get <VREQ-ID> --deep` gives the requirement, expression, and traces.
2. Reproduce with the smallest stimulus, one seed. Quote the first failing log line.
3. Open only the CODE region named by the check ID or the message ID; a generated tree has one block per check in `rtl_if/<tag>_checker.sv`.

## 3. Test first

Write the regression test (or the counterpart stimulus) before the fix and run it: it must fail for the right reason. Only then `vip bug set BUG-nnn regression_test=<name> status=fixed` after the fix. The log refuses `fixed` without a named test and `closed` unless the test is in the tree. A fix that is covered only by an old test is not accepted for `vip`-class bugs.

## 4. Fix rules

- Smallest change that explains the symptom; no refactoring, no renaming, no reformatting.
- No edits to `base/` of a generated VIP; a defect in the shared library is fixed in the flow repository and the VIP is regenerated by a feature run.
- Keep the VIP rules (`vip rules <PREFIX>`); MUST rules have no waivers.
- Keep default behavior unless the bug is the default behavior; if a fix changes observable behavior, say so in the release notes.

## 5. Impact and selective re-qualification

`vip impact` compares the fixed tree with the base tree and prints the scope:

| Changed | Scope | Re-run |
|---|---|---|
| a check block in `<tag>_checker.sv` | selective | the positive and negative trace of that check |
| a sequence in `seq_lib/` | selective | the traces of the requirements that name the sequence |
| a stimulus task in the counterpart, or a test | selective | that test |
| the coverage class | coverage | re-collect coverage; pass or fail evidence is not affected |
| the interface, check package, `base/`, agent, drivers, monitor, item, config, sequencer, package, any code outside those blocks | full | every trace |
| documents, filelists, spec copies, version strings | none | nothing |

`vip carry` builds the new evidence file (the regression test of each fixed bug that is not a trace of the matrix is added as an entry of kind `reg`, one per variant, so it runs and is judged like every other trace): entries that are PASS in the base evidence and not in the re-run set are carried (`log` is `carried:<base run>/...`), the rest are `NOT_RUN`. `vip qual-run --impacted` runs only the `NOT_RUN` tests. Gate 3 shows how many traces were re-run and how many carried. When the fix is in shared code, the scope is full and nothing is carried: that is correct, not a failure of the method.

## 6. Closing a bug

`verified` needs `evidence_log=<file>` that exists (the log of the regression run). `closed` needs the regression test in the VIP tree. A bug of class `dut`, or one that cannot be reproduced, is `wontfix` with a reason in `fix_summary`.

## 7. External code (layout external)

No plan, generated tree, or evidence matrix. Use the project's regression, `vip impact --files <changed files>` for the list, `05_qual/regression_report.md` for commands, logs, and results, the same bug transitions, and Gates 1, 3, 4. Anything not run is `NOT_RUN`.

## 8. Release

`vip bug report` produces the table for `release_notes.md` (bug, class, requirement, regression test, fix). The version is the base patch number plus one. `vip manifest` and `vip lint release` as in S6 and S7; Gate 4.
